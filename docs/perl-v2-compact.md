# Perl v2 compact prerelease

This is the `2.0.0-rc.1` prerelease, based on the scientific behavior of
the frozen `21e397ada04702330f4b90842197461e1108eb88` snapshot. This release
does not introduce a new timing result. The old helper scripts remain available; the matrix controller now
uses a single gene-tree parse and two processing phases.

The scientific operations remain explicit: label the reference, build its
primitive split axis, normalize gene observations, project complete reference
components, match those components, and assemble the matrices. Bit vectors
replace repeated taxon names in the gene processing stages. The reference
artifacts, aggregate truth and group tables, matrices, and fusion-cell table
retain their previous meanings and text representation.

## Run in a new output directory

Use the existing command syntax from the source directory, supplying input
paths relative to the output directory or absolute input paths:

```sh
perl /path/to/candidate/SplitAligner.pl --mode matrix \
  --species /path/to/reference.nwk --gene /path/to/genes.nwk --label trial
```

`--fusion-view whole` remains the default; `direct` keeps only values from one
normalized observation. Normalizing a displayed unrooted edge can combine
several input edge segments in either view. Whole-component sums must cover
complete reference components and preserve the existing missingness rules.

Do not run this candidate over a v1 result directory. `--force` deliberately
rejects the old per-gene layout. A new result namespace is required. Replacing
an intact compact result with `--force` uses the ownership and transactional
publication checks, including explicit recovery reporting on rollback failure.

### When publication reports incomplete recovery

Concurrent changes during publication can prevent automatic rollback. In the
P5 injection, the changed new object remains at its destination and the old
object is retained in a reported `.splitaligner-publish-backup-*` directory.
In E10, a backup changed after the old object moved is retained for inspection;
the destination can be absent. These outcomes preserve recovery material,
but **do not restore a valid complete run automatically**. A retained E10
backup must not be assumed to match the original bytes.

Stop other writers and preserve the entire failed output directory, backup
directory and error log before recovery. Use the reported destination/backup
mapping and the prior manifest hashes to identify which old objects remain
valid. Preserve an occupied destination separately; do not overwrite or delete
it merely to make recovery succeed. Restore old objects manually only after
their identities and hashes have been verified, then verify every owned output
against the prior manifest before treating the run as usable. If the old bytes
cannot be verified, rerun from the original inputs into a fresh directory.

Do not retry `--force` over a partially recovered run. Its ownership check is
expected to reject a mixture of an old manifest and changed or missing files.
An error message saying that recovery material was retained is not a success
receipt. The injected failures currently have nonzero exit codes that can
differ; callers must treat every nonzero exit as failure, rather than depending
on a particular numeric code.

## What is stored

The large `<label>_splits/` per-gene directory is replaced by:

| File | Purpose |
| --- | --- |
| `<label>.taxon_dictionary.json` | Sorted original taxon names, bit width and reference-axis identity |
| `<label>.compact.jsonl` | One evidence record per gene, in input order |
| `<label>.compact.index.json` | Input and ledger byte positions, record hashes, sorted output identities, complete fusion catalogue and limits |

The aggregate `<label>_split_branch_label/` directory still contains
`primitive_truth.tsv`, `projected_groups.tsv`, and `branch_patterns.txt`, with
the label prefix. Per-gene split, component and source-node TSVs are no longer
generated by default. Their information is in the compact ledger, including
gene observations that did not match a reference component.

Each JSONL record uses `splitaligner-compact-gene-v1`:

- `gene_id`, `input_record_id` and `input_line` bind the original input record.
- `tg` is the fixed-width, lowercase hexadecimal retained-taxon bit vector.
- `observations` are ordered by hexadecimal key. Their one-based array
  positions are observation IDs; each record contains a key, a **string**
  length token and `source_nodes`.
- `source_nodes` are zero-based Newick child-preorder node IDs, with root 0.
  They identify incoming source edges; these are not old split-file row IDs.
- `components` contain the complete reference-member set, projected key and
  an observation ID, or JSON null when not recovered.
- `truth`, `state`, and `primitive` follow the reference-axis order.

Bit positions follow the sorted taxon dictionary and Perl `vec` least-
significant-bit numbering within bytes. Padding bits must be zero. Hex keys
are only internal identities: scientific split text still uses the existing
canonical serialization, including its special-label codec.

The first phase parses each gene once and writes its complete JSONL evidence.
It reuses the kernel's already materialized result to write a private TSV
execution spool. The second phase reads one spool block at a time, verifies
its write-time hash and source binding, checks component/row consistency and
copies the scientific rows in sorted gene order. It constructs fusion cells
from the complete owners without decoding JSON or repeating reference
projection. There is no Tg cache in this candidate.

The spool is a temporary execution cache, not another independently derived
truth. It contains already formatted primitive/state/truth/group rows and one
entry per complete owner component; it binds the corresponding JSON block hash
and original record identity. Its offsets and hashes remain in memory, never
as permanent provenance locations. The file is removed before publication or
on failure. The only permanent source ledger is still JSONL, which the auditor
reads. The streaming hash of bytes written must agree with the staged ledger;
dictionary and index serialization seals are checked against the publication
inventory too.

`NA_fuse` remains a reference truth even when the corresponding group was not
recovered. State `U` is not itself an `NA_topo` classification. The catalogue
contains reference fusion patterns even if they were never directly recovered.
Changing whole/direct view does not change the primitive truth or group
recovery evidence.

## Audit an original gene

```sh
perl /path/to/candidate/scripts/audit_compact_gene.pl \
  --manifest /path/to/output/trial.run_manifest.json \
  --audit-gene gene_1 \
  --gene-input /path/to/original/genes.nwk \
  --species-input /path/to/original/reference.nwk
```

Repeat `--audit-gene` or use `--audit-gene-file` (one exact ID per line). If the
input paths recorded in the manifest still work, the two input overrides may
be omitted. Overrides must have exactly the original SHA-256; they cannot
substitute a different dataset.

The auditor verifies and temporarily freezes input and ledger bytes, reparses
the selected original genes, and compares every saved record field. It then
checks the selected genes' saved primitive matrix, full matrix, state, truth,
group, fusion-cell and gene-map rows against the reconstructed evidence. It
does not silently replace or repair a saved ledger. Missing original inputs,
wrong parser identity, changed bytes or semantic discrepancies are errors.

The successful JSON report includes the selected source records in input
order. Expanded records are spooled temporarily rather than retained as a
whole panel in memory. Scientific tables are checked one at a time. Auditing
therefore needs temporary disk space for the original inputs and ledger plus
the largest checked table; these snapshots are removed after the call.
No permanent second copy of the gene inputs is part of normal output.

This is a selected-gene source and row audit, not a fresh independent theorem
oracle or a revalidation of every unselected gene. The parser contract must
match the producer's recorded parser hash.

## Resource bounds and errors

Matrix mode retains one gene's tree and evidence, the reference, and
bounded index/catalogue metadata. It never assembles the complete scientific
matrix in memory. The retained finalize interfaces still use their previous
matrix-reading implementation. Current fixed limits are recorded in every index:

| Quantity | Limit |
| --- | ---: |
| Genes / fusion patterns | 100,000 each |
| Encoded index / fusion catalogue | 32 MiB each |
| Fusion member entries | 1,000,000 |
| Primitive plus fusion columns | 200,000 |
| Input line / scientific output row | 16 MiB each |
| One compact gene block | 64 MiB |
| One private execution-spool block | 64 MiB |
| Reference bit-vector payload | 64 MiB |
| Expanded evidence per audit call | 32 MiB |

Transient spool-index metadata counts against the index budget as well. The
temporary spool increases staging disk usage; it does not enlarge the permanent
ledger or scientific output set. These are payload/count limits, **not
peak-RSS promises**. Exceeding them is
reported before new results are published. The limits are not configurable
through the production CLI yet. Batch audit selections if their expanded
evidence exceeds the audit limit.

Gene validation and computation now happen together in private staging. If
multiple genes contain different errors, the first reported error can differ
from the old all-genes preflight order. Duplicate/unknown names, unsafe IDs,
malformed trees and invalid numeric inputs remain rejected, with the gene
identity and original label included where relevant.

The instrumented stage seconds on stderr cover disjoint internal regions;
they exclude some startup, hashing and publication overhead. They must not
be reported as total runtime. Full-panel timing, peak memory, platform
coverage and external review remain separate acceptance work.
